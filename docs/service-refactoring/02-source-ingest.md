状态：第三方转换、补链与严格去重已实现并通过本地隔离验收，尚未部署。更新：2026-10-26。本文取代旧采集 TODO，不再沿用准入测活、删除冷却和跨服务清理方案。

## 服务边界

服务只负责：读取来源 → 第三方解析 → 保存来源证据 → 完整配置去重 → 原子入库。缺少原始链接时，尝试生成可验证等价的链接。

独立入口、配置、数据库连接池、健康检查和容器；运行不需要 API、Redis、manager、Xray、Mihomo、出口或属性服务。数据库是存储依赖，订阅与文件是来源依赖；各来源适配器可以单独启停。

| 数据/行为 | 采集服务权限 |
| --- | --- |
| 完整连接配置、来源关系、别名、原始/生成链接 | 创建和维护 |
| available、last_available_at、测活事实 | 不更新；仅新节点初始化为未测且不可用 |
| 测活、出口、属性、恢复、删除任务 | 不创建、不消费、不触发 |
| 已有住宅属性、风险、出口与其他服务结果 | 不覆盖、不合并、不清理 |
| 来源失效 | 仅维护来源关系，不把节点判死，不删除主节点 |

只有 node-liveness 维护可用状态。采集提交后，测活服务自行发现待测记录；采集不调用它，也不等待结果。来源提供的成功、延迟和测速结果只作为来源证据，不得赋给本系统的可用状态。

subs-check 输出可以保留为输入适配器，但不能以其已测活为准入条件；能够直接读取原订阅的来源应直接采集，避免上游只输出成功节点造成采样偏差。来源不可达不等于节点不可达。

## 第三方组件与实现方向

采用 Sub-Store **2.44.2** 官方 `proxy-utils.esm.mjs` 的 `parse/produce`，通过私有适配器调用，不部署完整订阅管理应用。版本锁定并校验制品 SHA-256，本地协议回归已通过。

- URI、Clash YAML/JSON、订阅解码与协议转换使用第三方库，禁止继续扩展手写分享链接编解码器。
- 稳定 JSON 使用 `canonicalize@2.1.0`（RFC 8785），指纹使用标准 SHA-256；不自己写排序序列化器。
- HTTP 基础链接使用 Node 标准 WHATWG `URL` API 构造和解析，处理认证编码、IPv6；不手写转义。标准 URL 不能自动承载 SNI、跳过证书校验等代理扩展。
- 数据库驱动、迁移和健康检查使用成熟库，不引入自制队列。

推荐独立 Node.js 服务，直接使用 JS 转换库，与旧 Go worker 分离；最终锁定运行时、依赖版本和制品摘要。若保留 Go 入口，使用独立本地转换子进程适配官方模块，也不能退回手写协议。

Sub-Store 为 AGPL-3.0；保留许可及相应源码获取方式。canonicalize 为 Apache-2.0。适配器只接受文本，不开启远程脚本、任意转换 URL、远程处理器或 Sub-Store 持久配置。库会修改输入，每次调用需深拷贝；错误日志可能包含链接，必须改为无凭据错误码和计数。

## 原始链接与补链

1. 有原始 URI 就保存原始字节，不用生成链接覆盖；名称和 fragment 可另存为展示信息。
2. 同时有配置与 URI 时分别解析、比较。冲突不能静默选一个并把另一个标为等价。完整配置可形成节点，冲突 URI 作为未验证来源证据。
3. 只有配置时先保存完整配置，再尝试库导出 URI。输出为空、回读失败、多节点或参数不等价，都不能标为成功。
4. 原配置和回读结果通过库导出到同一配置格式后比较。只有具备协议依据及回归样例的别名/默认值可视为等价；未知字段和显式值差异不能忽略。
5. HTTP 普通端点可尝试 `http://`，TLS 可尝试 `https://`；SNI、证书校验、UDP 等额外设置必须通过目标客户端支持和往返测试，不能为补链删掉。
6. 按用户后续要求，无原始链接且无法生成链接的记录不进入节点主表，等待新服务重新采集补充；可在隔离的拒绝记录中标为 `unrepresentable`。缺少认证等关键参数则记录 `incomplete`，不能仅凭地址端口编造节点。生成链接仍须满足前述无损回读验收。

建议链接状态：`original / generated_verified / unrepresentable / incomplete / invalid`，另记验证状态、转换器与验证规则版本。`original` 是来源属性，不意味着有效。

历史链接档案仅作候选；同旧连接键匹配后也须验证配置等价。本次仅 2 条无链接记录有同键档案候选，且都是 generated，不能恢复成“原始链接”。

## 去重策略

### 第一期：严格配置去重

连接身份与来源出现记录分开保存。初期允许保留部分语义重复，优先避免错误合并。

- 完整配置仅移除明确的顶层展示/来源字段，初始白名单为 `name`、`sub_tag`；不递归删同名字段，保留未知参数及显式默认值。
- RFC 8785 序列化后，`fingerprint_version + SHA256(canonical_config)` 为唯一键；冲突时核对完整内容，摘要相同而内容不同必须报错。
- URI 经库转换成配置；未识别或不能保留的参数额外作为身份材料。无法证明无损的 URI 不能与已有配置自动合并；不得静默丢弃 query、插件选项后计算指纹。
- 原始输入完全一致用于来源事件幂等；原始链接文本不替代连接身份。相同连接可以有多个来源、名称和链接；不同凭据保持不同节点。
- 严格配置基线仅确认 1 组重复，旧连接键的 202 条候选冗余不能直接当成可删除数量。

### 第二期：版本化语义等价

协议转换器与本服务等价规则分别版本化。转换结果相等不足以证明连接等价，还须检查原输入的未知、删除和改写字段。无法证明无损时只做严格配置去重。

每条规则必须有第三方实现或协议依据及正反样例，例如 SNI 字段别名、端口数值类型、协议明确规定的默认传输。升级时先离线输出候选映射、审阅字段差异，不在启动时全表自动合并。

以下参数不能通用忽略：认证/UUID/加密、TLS/SNI/证书校验/指纹/Reality/ECH/ALPN、传输与 WS Host/path/headers、gRPC/HTTP/XHTTP、UDP、插件、复用、未知扩展以及 dialer/proxy 的实际引用语义。

不能按名称、国家、出口 IP、DNS 解析结果、可用状态或“协议+地址+端口”合并。域名解析到同一 IP 不证明节点相同。Sub-Store 默认按名称的去重算子不用于数据库去重。

## 存储与并发

下列模型已落为 `internal/ingestion/schema.sql`，以 registry 提供当前节点输入，不再写 snapshot_members 或整批快照：

| 对象 | 内容与约束 |
| --- | --- |
| connections | 稳定 node_id、完整配置、版本化指纹、first_seen；唯一 `(fingerprint_version, fingerprint)` |
| source_batches | 来源、抓取时间、内容摘要、成功/失败/部分成功、解析版本；批次幂等键 |
| source_occurrences | 来源批次、位置、node_id、别名、last_seen、来源有效期；允许多对一 |
| node_links | 原始/生成链接、来源记录、验证状态和转换器版本；多链接不覆盖 |
| rejected_items | 只保存位置、原因代码及批次；不落拒绝原文；无完整配置不混入可测节点 |

现有 registry 为跨服务事实表，不能通过整行或整个 node JSON 覆盖同步。过渡期只更新允许字段；已有 available、last_available_at、incarnation 等测活或并发控制字段保持原值，新节点显式 `available=false`。采集重放不重置测活。

使用数据库唯一约束和事务性 upsert，不用“先查后插”防并发重复。配置、来源关系和链接在批次事务中提交，重复连接只新增来源/别名、更新采集时间；重复批次不产生新节点。

只有来源全量成功才替换其当前成员关系；失败、截断、空结果或部分解析失败不能作为成功空全量覆盖。部分有效节点可入库，但保留旧成员，批次标为部分成功。文件适配器需处理半写与多文件非原子更新。来源退役只清理自有关系与批次，不级联删除节点及其他服务事实。

## 删除与清理范围

- 移除 source 路径的共享业务装配与 `runMonitor` 业务采样，只保留本服务健康和采集指标。
- 删除 `pruneCompletedWork` 等跨服务任务清理调用及仅供此路径使用的代码。
- 删除 source 对出口/IP 属性结果的历史清理；批次保留仅清理采集记录，不级联删除其他服务事实。
- 移除旧手写 sharelink/identity/connection_key 的采集调用，切换其他调用方后删除无用实现；不能保留第二条采集写入路径。
- 删除采集准入测活、恢复、永久删除、任务触发和可用状态同步；不恢复已删除的 recovery/dead-verify。
- 保留所需来源协议与配置兼容，不沿用旧代码的服务结构。
