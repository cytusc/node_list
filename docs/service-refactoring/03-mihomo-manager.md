## 当前职责与依据

这是共享 Mihomo controller 的唯一业务控制者；负责注册表读取、配置变化合并、重载、探测租约/容量、健康状态和全量/补偿巡检。manager 持有角色锁与 controller 所有权锁，丢失所有权会停止服务；不能让其他 worker 绕过它修改共享内核。

依据：[mihomo_manager.go](../../backend/internal/service/mihomo_manager.go)、[transport manager](../../backend/internal/transport/manager.go)、[sweep_runner](../../backend/internal/service/sweep_runner.go)、[巡检可靠性](../SWEEP_RELIABILITY.md)。现有代码已有重载隔离、代际保护、预期 204 验证和补偿重试，这些是保留项。

## 验收与回退

保留同一 identity 的观测串行化、取消后排空、config digest/incarnation/generation 防护，以及本轮有效预期 HTTP 状态证据校验；controller 返回 200 本身不构成目标可达。补偿集合只在数据库提交后更新，容量/网络控制故障不产生死亡证据。

结构调整执行后端检查及隔离环境真实 Mihomo 测试，报告内核版本与跳过项。双内核验收另做兼容性、成功率、误判、耗时、CPU/内存和兜底比例比较，不能把先前抽样当全量保证。保留原 Mihomo 路径作为可切回方案，切换需排空租约并隔离结果代际。
