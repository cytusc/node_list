# 批量连通性原型与独立压测

本次交付是隔离原型、实测结果和生产集成建议。生产检测仍保留恢复并发 16、普通连通性实例 20；没有替换线上检测器或更新节点状态。

## 实现

新增 `backend/cmd/connectivity-bench` 和 `backend/internal/connectivitybench`，复用已有 Mihomo 批量配置及逐节点监听端口。一个内核持有整个不可变批次，所有请求及对照结束后才允许下一次重载。批次最多 128 个目标，HTTP/SOCKS 兼容配置使用原生引擎，共享该通道的并发配额。住宅和普通通道分别持有独立内核。

检测证据保持 GitHub GET、HTTP 200、单次 12 秒、失败后等待 10 秒复试；确认失效前要求主机直连及独立节点对照都成功。配置不支持、缺失对照、取消、配置重载失败都不能确认节点失效。轨迹仅保留阶段、时间、耗时及错误类别，不记录节点连接材料。

首轮高并发暴露了对照负载问题：512 并发首次有 82 个目标因 reference 返回非 200 而降为对照不足，后续复测还影响了低档。补充状态码后，另一次同条件运行记录到 259 个目标的主机直连对照为 HTTP 429。低负载复查 8 个 reference 均返回 200，暂停后主机 GET 也恢复为 200；因此不能把这类差异解释成节点已坏，也不能只因 CPU 仍有余量就继续加线程。

已据此修正原型：分散对照节点，并仅合并同时进行的对照 GET，不缓存完成结果；每个跟随者都等待本次验证调用之后才完成的响应。实际对照请求另有 16 个并发配额。领导者同步持有不可变批次租约，跟随者取消不会使请求越过租约。原有两次目标检测、失败间隔和直连/独立节点均须成功的要求保持不变。

第一版修正仍未通过复测：`bounded-batch256-repeat1.json` 中 6 个目标的参考节点失败都来自同一 identity；16 并发复测也有参考节点失败，所有档位最终都未满足零对照不足的严格筛选。最近可用只能用于选择参考候选，不能保证其此刻仍可用。最终原型因此增加了同批次内的参考节点顺序回退：最多 3 个不同服务端，逐个实时 GET，保留全部失败轨迹和参考 identity；主机直连失败仍立即拒绝确认失效。HTTP 429 仍会使整个分档运行失格，不能用回退掩盖限流。新实验使用 `resilient-*` 前缀，与前两版结果分开保存。

数据库仅在采样时连接。启动参数和显式只读事务双重限制，采样后关闭连接；执行容器不加入数据库网络，也不接收 PG 凭据。生产 API、数据库结构、任务队列和状态提交代码均不变。工具拒绝生产控制器名称，专用实例不发布宿主端口。

操作方法见 [压测工具说明](../deploy/connectivity-bench/README.md)。原始 sample 含节点连接材料，仅存在服务器私有目录；仓库只保留紧凑脱敏汇总，不保存各档完整节点副本。

## 环境和方法

服务器 4 CPU、约 20 GiB RAM，Mihomo v1.19.27，生产业务同时运行。固定样本于北京时间 2026-10-19 00:20:54 捕获：128 个最近 30 分钟检测可用的节点和 384 个退役节点，按协议比例确定性采样；另有 16 个最近可用住宅节点同时检测。

| 协议 | 固定样本数量 |
| --- | ---: |
| VLESS | 270 |
| VMess | 59 |
| Hysteria2 | 53 |
| Trojan | 46 |
| Shadowsocks | 44 |
| HTTP | 26 |
| SOCKS5 | 12 |
| AnyTLS | 1 |
| TUIC | 1 |

基线为单目标模式、16 并发、20 个专用普通内核；批量模式为 4 个专用普通内核，分别测试 16/64/128/256/512 并发。两者均同时使用另外 2 个住宅内核。为避免干扰采样的时序，样本在各档间固定；每次判定中的对照请求仍实时执行。

基线与批量测试均为直接驱动传输层的连通性实验，不包含生产 Redis 调度、恢复协调器、强出口验证及状态写入时间，不能与线上完整恢复速率直接等同。整轮耗时包含全部排队和路径准备。基线及第一轮未修正原型的单节点 P99 从取得并发配额后计时；修正后的 `bounded-*` 及最终工具还计入批次准备耗时，检测证据要求相同。排队指标也包含准备耗时，不能与判定耗时直接相加。

固定样本中有 54 个配置无法加载（VLESS 21、Shadowsocks 17、VMess 9、Hysteria2 7）；基线和各批量档对应的节点身份完全相同。这些结果单列为 `unsupported`，没有确认失效，也不能用本次实验证明其实际不可用。吞吐分母是全部输入目标数，因此推荐配置时同时报告成功检测、确认失效和未能判定的数量。

## 实测结果

最终采用 `resilient-*` 结果。前两版只用于故障分析，没有纳入推荐。以下均为固定 512 个普通输入目标；另有 16 个住宅目标同步运行。

| 模式 | 普通内核 / 并发 | 耗时（秒） | 可用 / 确认失效 / 不支持 | 整机平均 CPU | 住宅排队 P95（毫秒） | 成功重载 |
| --- | --- | ---: | --- | ---: | ---: | ---: |
| 单目标基线 | 20 / 16 | 344.661 | 146 / 312 / 54 | 23.10% | 21.844 | 510 |
| 批量 | 4 / 16 | 370.453 | 136 / 322 / 54 | 25.62% | 70.161 | 4 |
| 批量 | 4 / 64 | 99.165 | 142 / 316 / 54 | 26.31% | 60.877 | 4 |
| 批量 | 4 / 128 | 61.604 | 142 / 316 / 54 | 24.93% | 53.423 | 4 |
| 批量 | 4 / 256 | 42.222 | 142 / 316 / 54 | 25.93% | 58.081 | 4 |
| 批量 | 4 / 512 | 35.168 | 141 / 317 / 54 | 26.90% | 41.245 | 4 |

| 候选并发 | 首轮 / 复测 1 / 复测 2（秒） | 三轮平均耗时（秒） | 平均吞吐（目标/秒） |
| --- | --- | ---: | ---: |
| 256 | 42.222 / 41.778 / 39.554 | 41.185 | 12.442 |
| 512 | 35.168 / 35.427 / 35.448 | 35.348 | 14.485 |

选择 **4 个普通内核、每批 128 个目标、总并发 512**，另保留 **2 个住宅内核及独立 16 并发预算**。512 比 256 的三轮平均吞吐提高 **16.4%**，超过优先选低档的 10% 门槛。相对 16 并发单目标基线，512 个输入的平均整轮耗时从 344.661 秒降至 35.348 秒，吞吐约 **9.75 倍**。

九次最终分档及复测均无对照不足、HTTP 429 或控制器错误；普通判定 P99 最大 27.560 秒，住宅排队 P95 最大 82.420 毫秒，整机平均 CPU 最高 50.66%，可用内存最低 10,004 MiB，均通过资源和延迟门槛。CPU 包含同期生产业务，不能把各轮差异全部归于并发档位。成功重载从 510 次降到 4 次；该计数不包含内核拒绝坏配置时的加载尝试。

保持 16 并发时，批量版本并没有提速。主要收益来自让多个节点共用一个不可变内核配置，并增加同时在途的检测数量，使网络等待及 10 秒复试间隔可以重叠；CPU 空闲并不表示单纯增加独立内核或线程就能得到同样收益。

固定输入保持不变，网络状态和内核缓存并不静止。分档顺序运行，因此下面另做新鲜的交替模式复核；不能拿最早基线的单次可用状态当作永久真值。

### 全部到期候选只读扫描

差异复核通过后，重新以只读事务捕获到期候选，共 **6,619 个输入，366.430 秒（约 6 分 6 秒）完成，吞吐 18.06 个/秒**。其中 696 个目标 GitHub GET 返回 200，5,773 个有完整失败和成功对照证据，150 个配置不支持；没有对照不足、HTTP 429、控制器错误或资源停止。

| 全量扫描指标 | 实测 |
| --- | ---: |
| 普通判定 P99 | 26.518 秒 |
| 普通排队 P95 | 323.444 秒 |
| 住宅排队 P95 | 48.494 毫秒 |
| 住宅可用 | 16 / 16 |
| 整机平均 / 峰值 CPU | 33.45% / 70.45% |
| 最低可用内存 | 9,950 MiB（约 9.72 GiB） |
| 普通批次 / 成功重载 | 52 / 52 |
| 独立对照执行 / 合并等待者 | 4,864 / 6,697 |

普通目标的排队时间随整轮输入增加，不能把获得配额后的判定 P99 解释成全部输入都在 27 秒内完成。15 个失败的参考尝试均在轨迹中保留，随后有新的独立参考成功，没有把失败结果缓存或当作成功。

采样要求任务仍匹配当前退役 identity、时间和原因，处于到期且未完成状态，注册表仍可用并有关联快照。生产台账中的排队任务数量与这个严格筛选后的输入数量并不相等。本轮只覆盖采样时的候选，任务队列仍由生产服务正常推进。**696 个连通性成功不等于 696 个节点已经恢复**：本实验未执行强出口验证，也未写入任何恢复或可用状态。

紧凑脱敏数据见 [实测数据](connectivity-bench-results-2026-10-19.json)，包含每轮聚合、原始报告 SHA-256 和差异复核结论，不保存节点连接材料或完整节点报告副本。

## 准确性和安全性

接受条件：复核后没有新确认的错误判定；住宅排队 P95 ≤ 5 秒；单节点判定 P99 ≤ 120 秒；整机平均 CPU < 70%；可用内存 ≥ 4 GiB。CPU > 85% 持续 30 秒、可用内存 < 2 GiB、控制器错误率 > 1% 时停止该档。高档吞吐提升不足 10% 时优先采用低档，候选档及相邻低档各额外复测两次。

逐节点比较发现 15 个普通差异节点及 1 个住宅差异节点。对普通差异子集交替运行两轮单目标与批量模式，每轮仍同步检测原来的 16 个住宅样本：普通节点中 6 个四次均可用、5 个四次均确认失效、4 个间歇性变化；住宅差异节点四次均可用。没有出现低档两次一致、高档两次也一致而结论相反的持续模式差异。

另外对 4 个间歇节点再交替检查两轮。`L` 表示目标 GitHub GET 返回 200，`D` 表示两次目标失败且直连和独立节点对照都返回 200；每组顺序均为单目标、批量、单目标、批量。

| 间歇节点协议 | 首次四轮 | 补充四轮 |
| --- | --- | --- |
| Trojan | DLLD | DDDD |
| Shadowsocks | DLLL | DDDL |
| HTTP | DDDL | LDDD |
| VMess | LLLD | LLLL |

这 4 个目标均为独立的服务端 IP，在固定样本中各只有一个对应服务端目标，未被用作对照或住宅负载；没有本实验对同一服务端重复并发的碰撞。低并发也复现了失败，成功可出现在首次或复试 GET，失败轨迹为连接层错误或超时。证据支持随时间变化的目标路径结果，没有发现可复现的批量新增误判；不能据此证明节点长期失效，也不能确定远端拒绝与线路问题各占多少。

已审查九次最终分档/复测及八次差异检查的全部判定证据：可用结果均含目标 HTTP 200，确认失效均含两次目标失败、直连 HTTP 200 和对应参考 identity 的 HTTP 200，未隐藏失败对照或限流。原型只输出诊断结果，没有生产恢复、退役或删除写入。

本地隔离数据库全量 `go test -race ./...` 已通过，另已通过 `go vet`。覆盖两次失败和对照不足、取消/超时、原生通道并发及身份映射、批次中坏配置隔离、128 目标加对照监听映射、内核租约隔离、重载失败释放、真实 PostgreSQL 写入拒绝、环境参数覆盖防护、资源停止门槛及输出文件保护。既有 generation/lease/incarnation/配置改变、恢复复核和删除前复核回归均保持通过。

另验证了对照请求只在执行期间合并、完成后必发新请求、不同 reference 不互相阻塞、等待者取消、全局及单 reference 配额释放。HTTP 状态诊断与原有 `transport.ProbeHTTP` 的 GET/URL/User-Agent/HTTP 200 判定逐项对比通过。

参考节点回退测试覆盖首个失败后第二个成功、最多三个参考节点、主机失败不能确认、HTTP 429 留在轨迹、取消时停止回退，以及成功对照身份正确归属。新增回退后的全量竞态测试及 `go vet` 再次通过。

压测后已停止监测并移除专用 Compose 容器及网络，删除 10 份私有连接样本或配置、7 个临时二进制。51 份无连接凭据的诊断报告和监测文件归入服务器私有压缩审计包，约 1.50 MiB，删除散落副本；仓库只保留约 80 KB 的脱敏聚合。8 个生产服务均健康、重启次数为 0，清理前后启动时间不变，生产 `.env` 和 `compose.yaml` 的 SHA-256 与实验前一致。

本次代码保留在独立工作树 `/tmp/node-list-recovery-tuning`，没有操作原工作区尚未完成的合并，没有提交、推送、发布镜像或替换生产检测器。

## 后续生产集成

1. 将常规巡检、住宅恢复、非住宅恢复的连通性任务接入统一批量执行接口，保留住宅资源与优先级隔离，出口验证使用独立资源。
2. 批次收集器必须领取并维护每个任务的租约；结果继续逐项通过既有 generation、token、incarnation 和配置改变防护提交，取消或过期任务不能写回。
3. 同步调整恢复协调器的在途 session admission。当前 16 个 session 会限制底层高并发检测器，单纯加快 Mihomo 而不调整 admission，线上恢复吞吐仍会受限。
4. 两次强出口验证及真实删除前的新鲜独立检测保持不变，分别测量连通性吞吐和完整恢复吞吐。
