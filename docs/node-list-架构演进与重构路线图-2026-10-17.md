## 2. 现状架构（容器级）

```
                    ┌──────────────────────┐
                    │  Qilan 面板(外部)      │
                    └──────────┬───────────┘
  subs-check(外部) ──文件──▶ source-ingest ──┬──▶ PostgreSQL(531MB, 外部)
                    │        (来源导入/注册)   │   · current_nodes 投影
                    │                        │   · snapshots(7天) / retired(无界)
                    │                        │   · ippure_results(无界)
        浏览器 ◀── HTTP :49327 ── node-explorer (API 查询, 只读 SQL)
                                       │
        connectivity(测活) ◀──▶ task-redis(任务引用) ◀──▶ ip-service(出口/属性)
             │ 8×Mihomo租约                │                    │ 8×Mihomo租约
             ▼                           ▼                    ▼
        residential-recovery(住宅核验) ◀──▶ node-lifecycle(退役/恢复事务+审计)
```

- 六个服务同一镜像、同一 Go 仓库，按 `-role` 启动；服务间**不直接互调**，经 PostgreSQL 事实表 + Redis 任务引用协作（设计正确，保持）。
- 凭据边界清晰：公开 API 去凭据；Redis 只放 `任务ID:代数`。
- 当前形态就是「模块化单体」的正确落地：**独立重启、独立扩缩、共享域模型**。路线图不再改这个形状。

## 5. 明确不做（YAGNI，防止范围蔓延）

| 项 | 理由 |
|---|---|
| 微服务化 / 拆仓库 | 六服务模块化单体已是正确形态；团队规模与问题域都不支持进一步拆分 |
| CQRS / 事件溯源 | 读写不对称度不够；当前 SQL 投影 + 任务表已解决 |
| 换存储 / 换队列（去 PG 或去 Redis） | PG 持久投递 + Redis 引用是故障恢复设计核心（Redis 丢消息不丢任务） |
| Qilan identity 二级归一 | 2026-10-14 实测否决（同键不同 uuid 是真实多账号，误合并风险），结论有效除非复测显示凭证轮换 |
| 看门狗 / 自愈 cron | 用户 10-14 确认：19h 停止是迁移窗口；无无人值守场景 |
| 前端框架迁移 / 状态库引入 | 当前 React 19 + 轮询够用；App.tsx 拆分是纯结构改善 |
