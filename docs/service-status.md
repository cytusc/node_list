# 服务状态面板

面向节点列表的使用者，首先回答检测服务是否运行、有无任务阻塞；需要时再查看检测结果和恢复记录。

## 设计

沿用页面的蓝灰色系：画布 `#f8fafc`、面板 `#ffffff`、正文 `#172b46`、运行 `#187553`、告警 `#99600b`、异常 `#dc2626`。深色模式复用现有主题，调整运行和告警色的对比度。字体沿用页面中文无衬线字体，数字使用 tabular-nums。

一张可折叠的 shadcn Table 承载所有服务，文字左对齐、数量右对齐；Badge 区分状态，Popover 解释口径，Button 负责刷新与逐行详情。避免每个服务一张卡片和持续闪烁的指示灯。设计复核后，去掉旧版九个信号灯和堆叠长说明，保留真正需要判断的任务列。

```text

────────────────────────────────────────────────────────────
服务          状态    到期待处理   定时等待   执行中   最长等待
共享测活内核  告警           —          —        3          —  ›
  隔离节点告警
连通性检测    运行           0      2,360        4          —  ›
住宅 IP 恢复  运行           0         35        0          —  ⌄
  核验中会话 / 已记录核验 / 最近一小时 / 冷却等待
────────────────────────────────────────────────────────────
每 15 秒刷新
```

手机保留服务、状态、待处理和执行中；定时等待、最长等待放进详情。数据过期提示在折叠状态下也可见，刷新与展开操作使用独立按钮。

## 数据口径

- `healthy` 保持服务心跳语义。面板另外显示配置隔离、配置拒绝和失效执行租约的告警，不把节点检测失败率当成进程故障。
- `running` 只含有效执行租约。共享内核使用 `kernel.fastRunning`；恢复服务的 `activeAssessments` 单列为“核验中会话”，包含等待前置检测。
- 住宅恢复的完成态冷却任务按调度器相同的身份、退役代次、来源、自动退役原因与退避周期筛选。冷却未到期计入 `scheduled` / `cooldown`，到期计入 `queued` 与最长等待。
- `restored` 是非演练恢复操作次数；`restoredNodes` 是对应身份去重数。
- 已记录核验按真实结果统计，包含失败和配置异常，机房 ASN 跳过单列。早期截断或缺失历史不推算为完整累计。
- 快速测活使用既有 Redis 分钟桶；上一分钟为完整分钟，小时数据是包含当前分钟的最近 60 个桶（实际 59–60 分钟）。界面明确标注。
- `/api/services.observedAt` 和状态列表一起缓存，表示实际查询时间。前端每 15 秒更新，12 秒请求超时；失败或快照超过 45 秒后取消绿色运行状态。服务心跳另按 90 秒判定。

## 持久化与发布

数据库 schema 升至版本 7。迁移从现有 recoveryHistory 或旧版 checkedAt/result 导入留存结果，不根据 recoveryAttempts 虚构丢失记录。`cancelled-historical-backlog` 不算核验结果。

新结果在任务完成的同一租约事务中写入 `node_explorer_recovery_events`，并仅对实际插入结果增加 `node_explorer_recovery_totals`。滚动明细保留两小时，累计表按服务和结果聚合，避免每次状态查询扫描无限增长的历史。节点或任务清理不删除累计统计。

发布时先暂停两类恢复消费者，运行新 worker 的 schema 初始化，再统一启动新恢复消费者与 API/前端，避免旧消费者在迁移完成后继续写入不带新统计的结果。发布前备份数据库。前端与 API 应同步升级；旧接口没有 observedAt 时，新面板会提示更新失败。

## 验证

Go 回归覆盖版本 6 升级、旧结果导入、取消任务排除、16 条历史上限、混合结果、重复投递、删除和滚动清理。PHP 集成测试覆盖新字段、冷却到期、失效租约、配置告警、恢复去重与历史统计。Playwright 覆盖刷新失败、过期数据、初次失败、详情保持、键盘操作、手机与深色模式。

本地已有其他应用占用默认端口时，可用 `PLAYWRIGHT_PORT=5178 npx playwright test` 指定测试端口。
